# Как выпустить релиз

Установщик для Windows и APK для Android собирает GitHub Actions (`.github/workflows/release.yml`) — локально ничего
собирать не нужно.
Релиз создаётся из **аннотированного тега** `vX.Y.Z`; текст релиза — сообщение этого тега.

## Шаги

1. **Версия.** В `package.json` поднимите `version` (например, `1.4.0`), закоммитьте и запушьте в `main`:

   ```
   git commit -am "Anix Desktop 1.4.0"
   git push public main
   ```

2. **Заметки к релизу.** Напишите их в файл, например `notes.md` (Markdown, как в прошлых релизах: что нового,
   как установить, про SmartScreen). Файл в репозиторий не добавляйте.
   Окно обновления в приложении показывает из них первую строку и список под строкой «**Что нового в X.Y**» —
   держите этот заголовок и пункты списком (`- …`); без него покажется весь текст.

3. **Тег.** Версия в теге должна совпадать с `package.json`, иначе сборка остановится:

   ```
   git tag -a v1.4.0 -F notes.md
   git push public v1.4.0
   ```

4. **Готово.** Через 5–10 минут (25–30, если менялся `trt/`) в
   [Releases](https://github.com/arigandores/anix-desktop/releases) появится «Anix Desktop 1.4.0» с
   `AnixDesktop-Setup-1.4.0.exe`, `latest.yml`, `.blockmap`, `Anix-1.4.0.apk` (Android — через минуту-две после
   установщика) и текстом из тега. С этого момента установленные
   приложения (версии новее 1.5.0 — в 1.5.0 автообновления ещё нет) при запуске предложат обновиться. Ход сборки — во вкладке
   [Actions](https://github.com/arigandores/anix-desktop/actions/workflows/release.yml).

## Платформы: релиз только для Windows или только для Android

Изменения часто касаются одной платформы — тогда и релиз только для неё. Строка в тексте тега (в `notes.md`):

```
Платформы: android
```

(или `Платформы: windows`; без строки — обе). Сборка выпускает только эту платформу, в релизе — только её файлы, и
приложение другой платформы обновления не увидит: оба ищут последний релиз со своим файлом (Windows — `latest.yml`,
Android — `Anix-X.Y.Z.apk`), а не просто последний. Версия общая и растёт всегда: после `1.7.0` для Android следующий
релиз для Windows — `1.7.1`, а не снова `1.7.0`.

Свои пункты «Что нового» у платформ — разделами после общего списка; каждое приложение показывает общий список и свой
раздел, строку «Платформы» не показывает:

```
Anix 1.7.0 — плеер удобнее.
Платформы: windows, android

**Что нового в 1.7**
- общее для обеих

**Windows**
- только для Windows

**Android**
- только для телефона
```

## Что делает сборка

- проверяет, что тег совпадает с версией в `package.json`;
- ставит зависимости и Electron;
- `anix-trt.exe` (ускорение NVIDIA): берёт из кэша, а если менялся `trt/` — ставит CUDA Toolkit 13.1 и собирает
  заново (на образе `windows-2022`: nvcc 13.1 не принимает Visual Studio 2026);
- кладёт ключи из секрета `CONFIG_LOCAL_JSON` в `config.local.json` — без секрета релиз не выпускается;
- собирает установщик (`npm run build:release`) и выкладывает в релиз его, `latest.yml` и `.blockmap`.
  По `latest.yml` приложение узнаёт о новой версии и проверяет скачанный файл (sha512), по `.blockmap` — докачивает
  только изменившиеся части. Без них автообновление новую версию не увидит.

## Android

Тот же тег — и та же команда: параллельно с установщиком для Windows собирается подписанный `Anix-X.Y.Z.apk`
(задачи `android` и `android-release` в `release.yml`) и кладётся в тот же релиз — по нему приложение на телефоне
находит обновление. Ничего отдельно запускать не нужно.

Подпись — из секретов `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
`ANDROID_KEY_PASSWORD` (уже заведены); без них релиз не выпускается. Сборка проверяет, что APK подписан ключом Anix.

**Все секреты и ключ подписи — копией в приватном репозитории
[arigandores/anix-secrets](https://github.com/arigandores/anix-secrets)**: что где лежит, как восстановить на новом
компьютере, и `sync-secrets.sh` — выставить все секреты GitHub заново одной командой. Ключ подписи Android не терять и
не менять: подписанная другим ключом версия не встанет поверх установленной, пользователям придётся удалить
приложение (с данными) и поставить заново.

## Пробная сборка без релиза

Actions → Release → **Run workflow** (ветка `main`). Установщик появится в артефактах запуска (хранится 14 дней),
релиз не создаётся. Или из консоли: `gh workflow run release.yml --ref main`.

## Ключи (секрет `CONFIG_LOCAL_JSON`)

Это весь `config.local.json` целиком (Kodik, StudioMir, VK Видео, соцвход, Discord). Поменяли ключи локально —
скопируйте файл в `anix-secrets`, закоммитьте там и выставьте секреты заново (`./sync-secrets.sh`) или только этот:

```
gh secret set CONFIG_LOCAL_JSON -R arigandores/anix-desktop < config.local.json
```

Ключи попадают внутрь установщика — секрет лишь не даёт им попасть в репозиторий.

## Если что-то пошло не так

- **Ошибка в сборке** — исправьте, запушьте в `main`, удалите тег и поставьте заново:

  ```
  git push public :refs/tags/v1.4.0
  git tag -d v1.4.0
  git tag -a v1.4.0 -F notes.md
  git push public v1.4.0
  ```

- **Опечатка в тексте релиза** — правится прямо на GitHub (Edit release), пересобирать не нужно.
